§01 · THE RECORD

The record

A Family Office Record (FOR) is one subject, every field sourced. The field is { value, source_url, read_by, read, state } — and where a second independent public source agrees, second_source_url and second_read_by. The record carries:

  • identity — legal name, jurisdiction, structure (single / multi-family / embedded / virtual), formation, registered office
  • registrations — each public register the office appears on: register, id, url, status, read
  • lei — the Legal Entity Identifier, the spine
  • principals — as disclosed on the register, no more
  • sectors — as disclosed
  • website · aliases (sourced) · events (dated, URL'd) · gaps (declared, with reason)

A field without a URL does not exist. Hearsay, directories that aggregate without citing, and model memory are not sources. Search is a way to find a source page, not a source. Records are confirmed, not signed: the office's signing has not shipped on this record.

§02 · STATES

States

  • sourced — one public source, read and dated
  • filled — completed by an engine from a source and not yet confirmed
  • confirmed — two independent public sources agree
  • conflict — sources disagree; both kept, none chosen
  • unverified — a constructed pointer, marked as such

Three passes: harvest (enumerate subjects from the spine register), fill (complete fields from source pages), confirm (a second source per field). Each node's as-of is its sweep start; nodes need not share a calendar date.

§04 · THE DOOR

The door

A Model Context Protocol (MCP) server plus an Agent-to-Agent (A2A) Agent Card: public, read-only, session-free, no authentication for reads, typed errors, real 404s. The apex door holds the index and forwards; the node door serves the record; nothing is stored at the apex. Five tools, the same names on every office graph:

  • resolve_family_office(identifier) — LEI, legal name, alias or register id to the records that carry it, with the node that serves each
  • get_record(identifier, version?) — the Family Office Record, every field with value, source_url, read_by and state
  • list_events_since(identifier, since?, cursor?, limit?) — dated, URL'd events, oldest first, paged
  • list_aliases(identifier) — every name the record carries, each with its source
  • list_nodes() — the nodes, with record counts read from each node's index
  • Apex door — https://mcp.fo-kg.ai/mcp · card /.well-known/mcp.json
  • Node doors — https://ca.fo-kg.ai/mcp … https://row.fo-kg.ai/mcp, one per node in §03; the node slug (ca-fo-kg) is unchanged on every record, index and card
  • Agent Card — https://agent.fo-kg.ai/.well-known/agent-card.json
  • Long names keep answering — mcp.familyofficeknowledgegraph.ai/mcp · <node>.familyofficeknowledgegraph.ai/mcp · agent.familyofficeknowledgegraph.ai; the short root is the door of record
  • Over HTTP — /resolve/{identifier} · records at /records/nodes.json
  • Paid call — /api (x402 v2, $0.01 USDC, Base mainnet) returns the graph index of record as a signed statement with a receipt · /x402
